# MAPP statistical pipeline V2 — review build

## Status and scope

V2 is a side-by-side analysis CLI and read-only explorer for new, immutable runs. Historical runs remain reproducible through `src/biostat_toolbox.r` and the root `renv.lock`; the older scripts `reprocess_stats.R`, `plot_selected_boxplots.R`, `analyze_spectral_modules.R`, and `generate_data_explorer.R` still consume legacy data and are not V2 readers. No scientific equivalence or replacement of legacy execution has been approved. The example methods and thresholds require MAPP scientific-owner review before production use. The Linux workflow below was exercised with R 4.6.1; macOS and independent Linux installation have not been verified.

V2 uses released Bioconductor [`ropls`](https://bioconductor.org/packages/release/bioc/html/ropls.html) for PCA and PLS-DA fitting and pinned `plotly` for the read-only interactive explorer; it does not load `MAPPstructToolbox` or `structToolbox`. Its pinned package environment is in `v2/renv.lock`, separate from the historical root environment. Install R 4.6.1 and, from `v2/`, run `rig run -r 4.6.1 -f bootstrap.R` (or `Rscript bootstrap.R` if the selected `Rscript` is 4.6.1). The bootstrap restores the pinned packages; after installation, analysis uses local inputs and does not fetch annotations or packages. `renv::status()` currently reports installed/recorded packages as *not used*: renv scans the isolated `v2/` directory, whereas the analysis modules and explorer live in `../src/v2` and `../app`. This is a dependency-discovery warning, not a missing-package warning; do not snapshot the root environment or drop pinned dependencies to hide it.

## CLI

From `v2/` with the pinned environment:

```bash
DATASET=../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/dataset.yaml
rig run -r 4.6.1 -f run.R -- validate --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/full.recipe.yaml
rig run -r 4.6.1 -f run.R -- plan     --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/full.recipe.yaml
rig run -r 4.6.1 -f run.R -- run      --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/full.recipe.yaml
```

`--` forwards options through `rig`. Direct `Rscript run.R validate --dataset ... --recipe ...` works when `Rscript` is R 4.6.1 and the `v2/` project is active. For a standard MAPP batch, author one static `dataset.yaml` with a batch ID, path to the batch, canonical metadata and quantification paths and optional annotation paths (see `configs/dataset.template.yaml`); the loader defaults to `sample_type` roles `sample`, `QC`, `blank` and feature ID `row ID`. Set `dataset.metadata_columns` or `dataset.roles` only for nonstandard batches; when both MZmine peak height and area exist, set `intensity_measure`. Put preprocessing, design group, optional `sample_plan` target mappings, enabled analyses and seed in separate per-analysis recipe YAML (see `configs/recipe.template.yaml`). The two batch 00275 recipes share the owner batch's dataset YAML; `batch_dir: ..` resolves canonical source locations relative to that file. The run hash includes actual source SHA-256 checksums, scientific mapping/recipe, code and pinned runtime; a separate recipe SHA-256 identifies equal parameters even when source data or code changes. Input hashes are calculated automatically and included in the manifest, never typed by hand. Automatically materialized recipes may carry a guard copied from their sealed source; it prevents accidental use if those files change. Output locations, descriptions, absolute paths and matching input-checksum guards do not affect run identity.

`validate` checks filename alignment, intensity values, roles, group replication, contrasts, and applicable design conditions. Metadata-only or quantification-only filenames fail explicitly rather than being silently excluded. A block must be experimentally verified and declared with `design.block_verified: true`; PLS-DA with a block is unsupported. `plan` previews feature attrition and destination without publishing a run. Examine blank/QC attrition and planned contrasts before `run`. A run stages tables, plots, objects, provenance and SHA-256 output checksums, then atomically publishes a `COMPLETE` marker. Repeating the same recipe with identical canonical sources and implementation reuses the completed hash without refitting. Existing completed hashes cannot be overwritten; corruption and incomplete runs require manual inspection.

For long CLI `run` operations, timestamped elapsed-time messages identify input validation, preprocessing, each enabled PCA/PCoA/omnibus/differential stage, PLS-DA, and export/sealing. In an interactive terminal, the supervised phase displays a 20-segment bar of completed held-out ropls fits across observed labels and all requested label permutations, then the full-data fit. With stdout/stderr redirected, stderr instead prints completed-fit fractions and percentages at five-percentage-point milestones or after ten seconds at the next completed fit. A single long model fit provides no intermediate percentage or ETA. `100% PLS-DA` precedes writing/checksums; only `Completed V2 run` confirms the sealed result. The reporting does not change preprocessing, random seed or statistical outputs.

The batch 00275 example validated 40 rows (30 samples, seven QCs, three blanks) and 2,114 features. With the current full recipe's minimum sample/blank ratio 2 and QC-RSD threshold 50%, `plan` removes 552 at blank filtering and 845 at QC-RSD, retaining 717. The merged recipe's ratio 5 and QC-RSD threshold 30% retain 427. Omitting `design.contrasts` requests all 15 unordered pairs of the six full-run biological groups when differential analysis is enabled; an explicit sequence of `{name, numerator, denominator}` entries overrides it. Each contrast has a separate static volcano PNG/PDF and a selectable saved result in the explorer. The A–E replicate labels are **not** treated as verified blocks. The alternate `mapp_batch_00196` example maps `mapp_sample_id`/`ATTRIBUTE_sample_type`, validates 94 rows (67 samples, 12 QCs, 15 blanks), and previews 4,792 retained features. Its example recipe disables inference and runs exploratory ordination without contrasts or PLS-DA. These are implementation checks, not biological approvals.

## Saved analyses and interpretation

Blank filtering precedes role restriction. Imputation, normalization, transformation and scaling operate on biological samples; QC-RSD filtering is optional. PCA uses the scaled matrix, nonnegative Bray-Curtis PCoA uses the normalized matrix, and linear-model omnibus tests/contrasts use transformed intensities. With log2 transformation a contrast effect is a log2 fold change. Reported Benjamini–Hochberg q-values are adjusted **per contrast across features**, not across the 15 contrast-by-feature families; do not interpret all-pair exploration as preplanned confirmatory testing. One-axis ordinations have saved one-dimensional plots. Output `sample_metadata.tsv` contains all input roles; `variable_metadata.tsv` contains the retained features; raw/blank-filtered stages include QC and blanks while later stages contain biological samples only.

The full batch 00275 recipe currently retains 717 of 2,114 raw features: 552 removed by blank filtering and 845 more by QC-RSD; the separate merged recipe retains 427 under its stricter thresholds. Blank filtering requires signal in at least half the blank injections **and** biological-sample median / blank median below the configured minimum ratio (2 for current full, 5 for merged). QC-RSD then excludes features above the configured threshold (50% full, 30% merged) or with non-finite RSD across QCs after half-minimum imputation and PQN normalization. Earlier-excluded features are not reconsidered. For each completed run, static **Overview** links its checksum-verified `blank_filter.tsv` and `qc_rsd.tsv` by feature ID to show the first exclusion stage and original measurements. Annotations and PCA/PLS-DA do not account for this feature attrition.

`analyses.omnibus.enabled` runs a per-feature full-versus-reduced linear-model **F-test** of whether any configured group means differ, without a direction. `analyses.differential.enabled` runs a per-feature, two-sided **t-test** for each configured numerator-minus-denominator contrast and reports the signed effect; with log2 transformation the effect is the log2 fold change. Both use retained, transformed biological-sample intensities and adjust p-values using Benjamini–Hochberg across features in their respective test family/contrast. For an unblocked two-group design, the omnibus F-test and its sole contrast t-test ask the same significance question ($F=t^2$); differential additionally supplies direction and magnitude. Neither is PLS-DA cross-validation or an additional feature filter.

Validated PLS-DA exports `tables/plsda_loadings.tsv` (`feature_id`, `LV1` through the saved full-fit component count) and `tables/plsda_vip.tsv` (`feature_id`, `vip`). Both are aligned to retained predictor IDs and come from the full-fit ropls model via [`getLoadingMN` and `getVipVn`](https://bioconductor.org/packages/3.23/bioc/vignettes/ropls/inst/doc/ropls-vignette.html); they are descriptive, **not** fold-held-out importance or independent biomarker evidence. The static **PLS-DA** tab shows selectable 2D/3D loadings with saved annotation colours, the top 50 VIP values, and a filterable all-feature VIP table. Runs without these optional files preserve their prior scores and validation. An OPLS S-plot would describe a different fitted model and is not mislabeled as part of the configured PLS-DA.

Bray-Curtis PCoA in this pipeline computes a sample dissimilarity matrix and applies [`stats::cmdscale`](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/cmdscale.html), which returns sample coordinates and eigenvalues, **not intrinsic feature loadings**. PCA-style variable coefficients cannot be assigned to its axes; a post hoc feature-to-axis fit would be a separately labeled descriptive analysis and is not exported as `pcoa_loadings.tsv`.

For raw peak inspection, `matrix_raw.tsv` retains every quantified feature before filtering, while `variable_metadata_input.tsv` retains its input MZmine metadata. `variable_metadata.tsv` remains limited to features surviving preprocessing and used in the analyses. A completed run records one configured intensity measure (`height` or `area`); batch 00275 supplies **peak height only**, not peak area.

Optional SIRIUS, CANOPUS and met-annot-enhancer inputs export separate candidate records and evidence rather than merging candidates across sources. Met-annot-enhancer's `organism_name` and `structure_wikidata` become candidate columns `organism` and `identification_links`, and `organism_wikidata` is retained. Reported taxon is source evidence, not the sample taxon or a confirmed identification. Optional `annotations.horizontal` (see `configs/dataset.template.yaml`) exports the saved `sources_number_IK2D`, source labels and `_SMILES` columns without inferring consensus from candidate rows; repeated feature IDs and unannotated measured features remain visible. A `validated` PLS-DA status means held-out CV and label permutations completed, **not** that discrimination was significant. Supervised preprocessing is fitted within each training fold; component count is bounded by training rank, not tuned by nested CV. The owner-repository full six-group recipe disables PLS-DA; the aggregated-group recipe enables 3 folds × 5 repeats with 99 permutations. Neither batch 00275 run has been executed since reset; no validation metric should be inferred from its design.

The published static dashboard's **Chemical classes** tab makes the saved CANOPUS `npc_pathway` → `npc_superclass` → `npc_class` → `feature_id` hierarchy browsable. Choose a categorical biological-sample metadata column and two groups to compare. At each branch, the filterable/downloadable table reports distinct feature counts, each group's mean *raw* intensity per sample, B/A and each child's percentage of its parent; the paired-bar plot shows the same percentages. Clicking a feature opens its saved evidence and descriptive intensity drawer. Only checksum-verified `annotation_candidates.tsv`, `sample_metadata.tsv` and `matrix_raw.tsv` are used. Predicted NPC classes are not confirmed identifications; these sums include measured CANOPUS-predicted features even if they were excluded from downstream statistical analysis, exclude features without CANOPUS predictions, and do not refit tests or normalize intensities.


## Read-only explorer

From the repository root, run `cd v2`. Batch 00275's ten old V2 runs were cleared; the owner has since produced multiple sealed analyses. The published dashboard currently indexes six, and the explorer can open any completed run from `v2/`:

```bash
MAPP_STATS_ROOT=../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275 \
  rig run -r 4.6.1 -e 'shiny::runApp("../app", host="127.0.0.1", launch.browser=FALSE)'
```

Keep that terminal running. Shiny selects a free port and prints **Listening on http://127.0.0.1:PORT**; open that URL on the server itself or use SSH forwarding below when the browser is on your laptop. For another batch, change `MAPP_STATS_ROOT` to its batch directory or an approved parent containing MAPP project/batch directories; never point it at `results/stats_v2` or a run hash. The explorer selects the newest completed run on opening, and **Refresh catalogue** selects the newest after a new CLI run. An unchanged effective recipe, canonical inputs, code and runtime reuse the same immutable run hash.

### Access from another machine

If the Shiny command runs on `commons-server` but your browser runs on a laptop, the printed `127.0.0.1` URL refers to the **server**, not the laptop. On the laptop, in a second terminal, forward the port printed by Shiny (replace `NNNNN` with that server port):

```bash
ssh -N -L 43117:127.0.0.1:NNNNN allardpm@commons-server
```

Keep both terminals running and open **http://127.0.0.1:43117/** on the laptop. If laptop port 43117 is already occupied, use `43119:127.0.0.1:NNNNN` instead and open `http://127.0.0.1:43119/`. This tunnel keeps Shiny bound to the server's loopback interface; do not change its `host` to `0.0.0.0` just to reach it from your laptop.

### Navigate the result

1. **Overview** shows input and selected sample counts, feature counts and annotation coverage. **Descriptive grouping / point colour** and **Sample role filter** change the visible subset, not stored test results. **All groups** is on by default; turn it off to choose a subset under **Groups to show**. In any interactive plot, click a legend entry to hide/show that group or double-click it to isolate that group; double-click again to restore all traces. The example defaults to `ATTRIBUTE_mutant`, for which QC and blank group labels are missing. To see QC or blanks, choose `sample_type` as the grouping and `QC` or `blank` as the role.
2. **PCA** and **PCoA** plot saved biological-sample scores. Choose independent X and Y axes, and 3D/Z when at least three components were saved. Axis and grouping controls redisplay saved scores, never refit them. PCA has a separate feature-loadings plot; click a loading point for the Feature explorer drawer. A score point is a sample, not a feature, and Bray-Curtis PCoA has no intrinsic feature loadings. The published batch 00275 full run's **Volcano plots** offer its 15 pairwise contrasts; batch 00196 has no planned contrast.
3. **Feature explorer** takes the full page width instead of showing the dataset sidebar. Select a Feature ID at the top, or click a candidate or consensus-table ID. Matching saved 2D InChIKeys across GNPS, ISDB and SIRIUS share one representative depiction in a horizontally scrollable gallery, even when their SMILES differ; differing or unavailable keys are not silently merged. Expand the card to read each source's original SMILES. One to three named source stars indicate which tools have that 2D key, not confirmed structure identity. The ISDB star has a tooltip with the saved taxonomic score and reported organism; a pale-yellow-to-bright-green 0–8 visual scale shows increasing score, and missing scores remain neutral. A saved `MS1_match` library entry is not labeled ISDB. The descriptive group box plot is shown beside the gallery by default (uncheck **Show feature intensity plot** to hide it), with medians, quartiles, whiskers and individual samples. Directly beneath the gallery and plot, a compact, internally scrollable table contains **all saved candidate records for the selected feature**, independent of the browse filters further down the page; click a candidate row to focus its source-specific evidence without clearing the search. Narrow screens stack the gallery, plot and selected-record table. To change **Saved intensity stage**, grouping, sample roles or groups, visit another tab's dataset sidebar and return; those controls continue to govern the feature plot. Changing the completed run clears the selected feature. Extended measured metadata and candidate details remain in the collapsible section below. For plot-point selection only, a collapsible right-side **Feature explorer** drawer opens with the same feature's details and intensity plot; close it with **Close** and reopen it with its right-edge tab. The open drawer narrows the plots instead of covering them. Use `raw` or `blank_filtered` for QC/blanks; later stages contain biological samples only. Every measured feature is available at the raw stage; if filtering removed it from the selected stage, the plot explains the saved filter decision and uses raw peak height/area instead. Annotation-only IDs absent from quantification have no measured peak. Older runs without `variable_metadata_input.tsv` can plot saved raw peaks but cannot show input metadata for filtered features. These views never recompute statistical tests.

   **Feature ID** is the unique measured-variable ID within a dataset (for example, feature `467`). Multiple annotation sources can propose candidates for that same feature. In the saved `annotation_candidates.tsv`, `candidate_id` is only a **source record key**: `sirius:402` and `canopus:402` denote row 402 in their respective source inputs, while `met_annot_enhancer:313` denotes row 313 in its input. Each of those records retains `feature_id = 467`; neither 402 nor 313 is another feature ID. The viewer labels these values as source record keys; the underlying TSV field remains `candidate_id`.
4. **Feature explorer** includes a saved InChIKey2D agreement selector (0, 1, 2 or 3 sources) when horizontal annotation evidence is present. Counts come directly from `sources_number_IK2D`, not reconstructed from candidate rows; missing counts remain under **All**. Search candidate records by ID, source key, name, InChIKey, taxon or NPC classification, and choose columns or page through all matches. Clicking an ID shows saved source-specific structures and evidence; reported taxa and Wikidata links are evidence, not confirmed identities. A run without the optional horizontal table explains the unavailable filter. PLS-DA displays held-out predictions and permutation results only for runs that enable it; batch 00275's full recipe disables PLS-DA and its merged recipe enables it.

The dataset/metadata sidebar is present on the other tabs and hidden in **Feature explorer**. All annotation controls live on the explorer page: Feature ID selection, candidate source, consensus, NPC classifications, an exact **Reported taxon (ISDB reponderated only)** selector and **Search reported taxon** for case-insensitive partial names. Both taxon controls use saved `organism` values on `met_annot_enhancer` candidate rows and combine when used together. They restrict candidate counts, the browse table and evidence choices, not samples, the selected feature's full structures, its pinned candidate records or the saved horizontal consensus list. An incompatible candidate source and taxon yield no candidate matches. Reported taxa describe previous candidate occurrences, not experimental sample origins.
5. In the top-right Plotly toolbar, **Download plot as a PNG** exports the *currently displayed interactive plot*, including selected 2D/3D dimensions, filters and legend visibility (PCA sample scores, PCA feature loadings, PCoA, volcano, PLS-DA and feature box plot). Separate **Download verified saved PNG/PDF** buttons under PCA, PCoA and volcano serve checksum-verified *unfiltered original 2D analysis plots*, not the newly selected dimensions. For tables, **Provenance & downloads** lists recorded inputs, effective recipe, environment and output checksums: choose an **Existing saved table** and **Download verified TSV**. Offline files remain under `<batch>/results/stats_v2/<run_hash>/plots/` and `tables/`.

In the published static dashboard (not the Shiny explorer), a plot-driven **Feature explorer** drawer offers **Detach to window**. Move that window to another screen while browsing the main plots: the selected feature, run and group colours stay synchronized. Select a feature in the detached window to update the main explorer, or choose **Reattach here** to return the details to the main dashboard. The new window must be allowed by the browser and served from the same dashboard origin; if blocked, the inline drawer remains usable.

On the static dashboard, **Display options · feature colours** on PCA and PLS-DA feature loadings and Volcano offers **Saved 2D-key agreement (0–3 sources)** and **Saved ISDB taxonomic score (0–8)** when their columns are present in `annotation_horizontal.tsv`; numeric measured fields such as m/z and retention time also appear when available. Numeric values use a continuous Viridis colourbar with fixed 0–3 and 0–8 ranges for agreement and score, respectively; measured fields span their saved range. Zero is not missing, **Not recorded** means no saved value, and contradictory saved rows appear as **Multiple values** in separate, editable colours. Categorical annotations retain individual colour pickers. **Candidate record source** instead groups `annotation_candidates.tsv` records (SIRIUS, CANOPUS classes, `met_annot_enhancer` for ISDB/MS1 evidence); GNPS agreement need not have a candidate record, and selecting a source in Feature explorer does not recalculate the saved count.

For the published static dashboard, feature-intensity stage, grouping, sample role, facets, visible groups and **Display options** open state are stored in the browser per sealed run. They survive changing features, switching between full explorer and inline drawer, reloading, and revisiting that run. The detached same-origin window uses the same settings; an unseen run starts with defaults. Clearing site storage removes these display-only preferences, without modifying saved analyses.

The explorer is read-only: it checks sealed objects without deserializing them, verifies TSV checksums before parsing or downloading, and rejects symlinked run files outside the approved root. Filters never recompute or relabel inference. For available SMILES, the browser loads SVG depictions from the [Natural Products Cheminformatics API](https://docs.api.naturalproducts.net/) using its [`/latest/depict/2D` endpoint](https://api.naturalproducts.net/latest/depict/2D?smiles=CCO); it sends SMILES and the browser's network address to that external service, which is not a sealed run output. If it is unreachable or rejects a SMILES, the saved SMILES remains available in the structure card. For an internal server configure host, access controls and port externally; do not expose this explorer directly to untrusted networks.
