# MetaboAnalyst web uploads for batch 00280

This is a **format/workflow reference, not an online upload test**. It uses MetaboAnalyst's current [Data Formats](https://www.metaboanalyst.ca/docs/Format.xhtml), [module overview](https://www.metaboanalyst.ca/MetaboAnalyst/home.xhtml) and [update history](https://www.metaboanalyst.ca/docs/UpdateHistory.xhtml) (site identifies itself as 6.0; homepage last updated 2026-11-04). The [tutorial index](https://www.metaboanalyst.ca/docs/Tutorials.xhtml) explicitly warns that older screenshots may not represent the current interface. Batch 00280 is **already peak-picked**: its [dataset recipe](../../laure-weisskopf-group/docs/mapp_project_00016/mapp_batch_00280/recipes/dataset.yaml) names `results/mzmine/mapp_batch_00280_quant.csv`, feature key `row ID` and intensity measure `height`; use the [treated metadata](../../laure-weisskopf-group/docs/mapp_project_00016/mapp_batch_00280/metadata/treated/mapp_batch_00280_metadata.tsv) to select biological injections and factors.

## Exact tabular shapes

- **Statistical Analysis [single factor]:** CSV (`.csv`) or tab-delimited text (`.txt`), either orientation. For **features in rows**, the first line is `Sample,<sample_A>,<sample_B>,…`; the **immediately following** line is `Label,<class_A>,<class_B>,…`; every later line is `<feature_ID>,<height_A>,<height_B>,…`. These are literal headers in the official [LC-MS intensity example](https://api2.xialab.ca/api/download/metaboanalyst/lcms_table.csv): `"Sample","ko15","ko16",…` then `"Label","KO","KO",…` then `"200.1/2926",147887.53,…`. For **samples in rows**, first column holds sample ID and the **second column its class** (the illustrative first line can be `Sample,Label,<feature_1>,…`); labels may be strings or 0/1 for *unpaired* groups. Choose the web module's matching samples-in-columns/rows and unpaired option; a timepoint or treatment is a *chosen comparison*, not an extra row in this single-factor matrix. [Format: CSV/text, row/column orientation, labels and LC-MS screenshot](https://www.metaboanalyst.ca/docs/Format.xhtml).
- **Statistical Analysis [metadata table] / covariate analysis:** upload **two** files: an abundance table *without the single-factor `Label` row*, with header `Sample,<sample_A>,<sample_B>,…` and subsequent `<feature_ID>,<height_A>,<height_B>,…`, **plus a separate sample-by-descriptor metadata CSV/text**. The official [time-series abundance example](https://api2.xialab.ca/api/download/metaboanalyst/cress_time.csv) starts `Sample,S1T0,S1T1,…` followed immediately by a feature; its [metadata partner](https://api2.xialab.ca/api/download/metaboanalyst/cress_time_meta.csv) starts `Sample,Phenotype,Time,Subject` / `S1T0,WT,0,S1`. The general [covariate example](https://api2.xialab.ca/api/download/metaboanalyst/TCE_metadata.csv) starts `Sample,TCE_Exp_Category,TCE_Exp_Conc,Age,Sex,Smoking_Status,Alcohol_Use,BMI,Batch` / `X1014,Low,0.025,28,Male,Yes,Yes,20.3,10`; its [abundance partner](https://api2.xialab.ca/api/download/metaboanalyst/TCE_feature_table.csv) starts `"Sample","X1014","X1049",…`, **no** `Label`. Metadata first column must exactly match abundance sample IDs; the **next** column is the primary variable of interest, remaining columns may be categorical factors or continuous covariates. Metadata cannot have empty/`NA` values, and categorical groups require **at least three replicates**; users can inspect/correct inferred metadata types and group order in the web integrity check. [Format: metadata requirements](https://www.metaboanalyst.ca/docs/Format.xhtml); [official web metadata walkthrough, pp. 5–7](https://api2.xialab.ca/api/download/metaboanalyst/7_Statistical_analysis_metadata.pdf).
- **Time-series analyses in that metadata module:** official specialized layouts require a `Time` column and a `Subject` column for balanced, repeated subjects; with an experimental factor, that factor is named `Phenotype` (example above). Order the same subject's timepoints consecutively. These are requirements for the *time-series design*, **not** a license to label all 00280 rows as balanced repeated observations; use only verified complete-plant subsets if invoking time-series/ASCA/MEBA, and do not infer repeated subjects from filename similarity. A generic multifactor/covariate upload can instead put chosen primary phenotype first and other complete factors (e.g. timepoint and batch) after it, without claiming the specialized balanced design. [Format: time-series and metadata](https://www.metaboanalyst.ca/docs/Format.xhtml); [module overview](https://www.metaboanalyst.ca/MetaboAnalyst/home.xhtml); [complete-plant recipe](../../laure-weisskopf-group/docs/mapp_project_00016/mapp_batch_00280/recipes/study_complete_plants.yaml).

## Recommended 00280 artifacts and safeguards

1. A **biological-only, unpaired, one-factor peak-height CSV** with preserved, unique `row ID` feature labels and explicit sample IDs/class row for one **preselected**, biologically coherent comparison. Create separate comparison-specific files if class definition changes; do not put pooled QCs or extraction blanks into biological case/control labels. If a true *paired two-group* upload is desired, the one-factor format has a different **signed-integer class-label convention** (`-1…-n/2`, `1…n/2`, matched by absolute value) and even sample count; ordinary phenotype labels do **not** encode pairs. [Format: paired vs unpaired](https://www.metaboanalyst.ca/docs/Format.xhtml); [treated metadata: sample types and plant IDs](../../laure-weisskopf-group/docs/mapp_project_00016/mapp_batch_00280/metadata/treated/mapp_batch_00280_metadata.tsv).
2. A **biological-only metadata-module abundance CSV**, identical sample-to-feature heights/IDs but **no** `Label` row, paired with a complete `Sample,<primary_factor>,<other_factors>…` CSV. Derive matched sample IDs from the curated metadata (not `.mzML` paths or QC/blank filenames); put a real biological primary factor immediately after `Sample`, and timepoint, batch and validated plant ID as appropriate after it. Only include metadata columns with values for **every** selected biological sample; choose a valid subset rather than inventing factor values. Treat numeric-coded batch/time as the intended category where appropriate in the web metadata integrity check. The metadata format places no QC-special `QC` label requirement on this *pre-picked statistical table*. [Format: metadata](https://www.metaboanalyst.ca/docs/Format.xhtml); [web metadata walkthrough pp. 5–7](https://api2.xialab.ca/api/download/metaboanalyst/7_Statistical_analysis_metadata.pdf); [treated metadata](../../laure-weisskopf-group/docs/mapp_project_00016/mapp_batch_00280/metadata/treated/mapp_batch_00280_metadata.tsv).
3. **Optional separately flagged QC inspection**, not biological inference: the [2026-07-31 web release note](https://www.metaboanalyst.ca/docs/UpdateHistory.xhtml) says `QC` and `BLANK` samples are kept out of differential analysis and may be dropped after the data overview (so they can first appear in PCA). This newer behavior does **not** justify labeling them as phenotypes, treating a blank as a negative biological replicate, or adding metadata with fabricated biological factors. The mandatory two-column metadata `.txt` with class `QC` is specified for **raw-spectra processing**, *not* for an already extracted intensity table. [Format: raw-spectra metadata](https://www.metaboanalyst.ca/docs/Format.xhtml).

For abundance cells, emit finite numeric measured **positive** heights, and empty cells or `NA` for genuinely absent values; no embedded spaces/thousands separators (`1 600` is misread). The written rule says positive values, yet official [LC-MS](https://api2.xialab.ca/api/download/metaboanalyst/lcms_table.csv) and [time-series](https://api2.xialab.ca/api/download/metaboanalyst/cress_time.csv) example matrices contain literal `0`. Thus zero clearly occurs in published examples but is **not documented as equivalent to missing**: distinguish measured zero from an undetected MZmine feature, do not fabricate positive heights, and document any zero→missing decision rather than assuming silent imputation. Abundance and metadata have different missing-value rules: `NA` is allowed in **heights**, forbidden in **metadata**. Feature and sample names should be unique; use stable ASCII letters/digits/underscores (the format page forbids Latin/Greek characters, while [2026 release notes](https://www.metaboanalyst.ca/docs/UpdateHistory.xhtml) describe duplicate-ID merging, so avoid relying on automatic merging when preserving `row ID`). [Format: numeric/missing/naming](https://www.metaboanalyst.ca/docs/Format.xhtml); [2020-06-29 default minimum-value replacement and 2025 missing-method changes](https://www.metaboanalyst.ca/docs/UpdateHistory.xhtml). The current Data Formats page states **50 MB for zipped spectra/peak lists** and **200 MB for raw-spectra online ZIP processing**, but does **not state a size cap for plain peak-height CSV/TXT**; do not transfer either ZIP cap to these CSVs. [Format: size limits](https://www.metaboanalyst.ca/docs/Format.xhtml).

## Functional LC-MS is a distinct upload

[Functional Analysis / MS Peaks to Pathways](https://www.metaboanalyst.ca/MetaboAnalyst/home.xhtml) accepts a peak-list `.txt` (v2 named columns up to `m.z`, `r.t`, `p.value`, `t.score`, `mode`; `r.t`/`rt` for retention time), or a generic/MZmine **peak table** `.csv`/tab-delimited `.txt`; an official [generic table](https://api2.xialab.ca/api/download/metaboanalyst/malaria_feature_table.csv) begins `Sample,Naive_007,…`, `Label,Naive,…`, `85.065__24.64,…` (m/z and RT encoded in feature name). The [format page](https://www.metaboanalyst.ca/docs/Format.xhtml) specifies that a three-column peak list with m/z, p and score supports mummichog + GSEA, while only p or only scores restricts algorithm choice. Its [6.0 LC-MS functional tutorial, pp. 4–9](https://api2.xialab.ca/api/download/metaboanalyst/5_Functional_Analysis_with_MS2_results.pdf) recommends **complete** MS1 features including nonsignificant ones, m/z, RT and p for meaningful interpretation, with t scores recommended; optional MS2 *candidate* lists have their own matching/index requirements. [2026 web updates](https://www.metaboanalyst.ca/docs/UpdateHistory.xhtml) additionally describe peak-table + candidate upload, m/z–RT separators `__`, `_`, `@`, `/` and case-insensitive m/z column names. Those releases are newer than some format-page examples; **do not assume an arbitrary `row ID` feature name can be parsed as m/z/RT**. If exporting a functional table, derive numeric m/z and RT from source MZmine columns, keep a separate reversible mapping to original `row ID`, and use an appropriate chosen *unpaired two-group* comparison for web-generated tests. Precomputed peak lists need valid p/score from that comparison, not uncomputed placeholders. A SIRIUS hit is a **putative candidate**, not a confirmed compound; do not substitute candidate names/KEGG IDs into a named-compound pathway/enrichment upload. [Format: functional inputs](https://www.metaboanalyst.ca/docs/Format.xhtml); [module overview](https://www.metaboanalyst.ca/MetaboAnalyst/home.xhtml); [2026 update history](https://www.metaboanalyst.ca/docs/UpdateHistory.xhtml).

**Not interchangeable:** spectra ZIP/mzML/mzXML/mzDATA workflows redo upstream peak picking; validated mzTab-M 2.0 is another statistical import format whose metadata parser may exclude `Blank` and whose feature IDs may be synthesized; peak-list ZIPs are per-spectrum files, not a single MZmine height matrix. None is the proposed pre-picked CSV export. [Format: mzTab, ZIP, raw spectra](https://www.metaboanalyst.ca/docs/Format.xhtml); [module overview](https://www.metaboanalyst.ca/MetaboAnalyst/home.xhtml).
