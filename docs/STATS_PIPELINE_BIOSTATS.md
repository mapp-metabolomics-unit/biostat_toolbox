# Biostats

The [quickstart](../README.md#run-a-batch) has the workflow: create a **study** with `cargo run`, run **validate**, **plan**, **run**, then optionally create any number of **comparisons** with `cargo run -- --batch <batch> --study <full-study-hash>` and run the same three commands for each. `run` seals each result and republishes the static dashboard and results README. Use R 4.6.1 and initialize the pinned `biostats/` environment once with `rig run -r 4.6.1 -f bootstrap.R` from that directory.

## Inputs and design

- Before opening the TUI or running stats, run `scripts/enrich_metadata.py --batch <batch directory>`; by default it scans `/media/nvme8tb/msdata/<project>/<batch>` derived from the batch path. Override that directory with `--mzml-dir <directory>` or `MZMLWATCHER_SCAN_DIR`. The helper invokes `mzmlwatcher scan` with SHA-256, saves SQLite/TSV artifacts under `results/mzmlwatcher/`, then enriches the existing treated metadata; see the [quickstart](../README.md#run-a-batch). Injection order comes from timezone-aware mzML acquisition timestamps, not metadata row order or filesystem modification times. RAW and converted mzML SHA-1 values are embedded in the mzML provenance; `converted_mzml_sha256` hashes the on-disk converted file. Match failures or ties must be resolved against acquisition records rather than guessed.
- A batch-owned `dataset.yaml` points to curated sample metadata, MZmine quantification, and optional annotation sources. `sample_type` defaults to biological `sample`, `QC`, or `blank`. Set `intensity_measure` when both height and area are available. See [dataset template](../configs/dataset.template.yaml).
- A batch-owned **study** recipe defines shared preprocessing and PCA/PCoA for its selected biological samples; by default that is every biological sample. On the TUI **Groups** page, optionally choose one or more study filter fields and include metadata values. For example, include `ATTRIBUTE_extraction_phase = I1`, or `ATTRIBUTE_part` values `Greenpatch` and `Yellowpatch`. Within each field values combine with OR; across fields conditions combine with AND. Only biological samples are restricted: QC and blank injections remain available for configured blank/QC feature filters and optional PCA/PCoA inclusion. A manually authored study recipe uses `study_filters: [{column: ATTRIBUTE_extraction_phase, values: [I1]}]`. A new study is required to change the selection; its comparisons inherit that subset and cannot bring excluded samples back. See the [study template](../configs/recipe.template.yaml). A batch-owned **comparison** recipe references the sealed study hash and defines further group selection, contrasts and optional inferential analyses; see the [comparison template](../configs/comparison.template.yaml). The Rust TUI checks metadata against quantification filenames; verify mismatches against acquisition records before approving a corrected metadata **copy**. It does not change the original files.
- Independent biological replicates are required for inferential comparisons. Do not silently pool repeated parts of the same specimen. `validate` checks alignment and design; `plan` reports study filter attrition or comparison reuse without publishing. Review both before `run`.
- `run` requires the toolbox checkout to have a valid Git HEAD and no staged changes, modified tracked files, or untracked nonignored files; this applies even when reusing a completed result. `validate` and `plan` still work while editing. Newly sealed study and comparison manifests save the full `environment.git_commit` plus per-source checksums; if HEAD or source bytes change during a run, sealing fails. The input metadata, quantification and annotations are separately checksummed.
- SIRIUS `structure_identifications.tsv` is read as literal tab-separated fields: quotation marks inside chemical names are data, not row delimiters. Other annotation TSVs keep their existing quoting rules.
- Under Settings in the Rust TUI, PCA and PCoA each have separate **include QC** and **include blanks** switches (off by default). In a manually edited recipe, set `analyses.pca.include_qc`, `analyses.pca.include_blanks`, `analyses.pcoa.include_qc`, or `analyses.pcoa.include_blanks` to `true`. Selected injections enter that ordination's fit after the configured feature filters and preprocessing; they may change its axes and are labeled separately in score tables and plots. Omnibus, contrasts, and PLS-DA still use biological samples only. With PQN or log transformation, blank injections dominated by zeros can be imputed and visually misleading; inspect their raw intensities before interpreting their positions.
- Interactive PCA score and loading axes show the percentage of total variance explained by the selected component, read from the sealed study's `tables/pca_variance.tsv`. Changing the displayed PC axes updates their percentages without refitting; older runs without that saved table retain plain component labels.
- The dashboard **Overview → Preprocessing quality and retention** links measured-feature detection, blank support, pooled-QC RSD support and QC-order diagnostics to feature explorer. These tables distinguish measured absence from an imputed value; a QC order association is not proof that correcting it is appropriate. In a selected comparison, the same checksum-verified study preprocessing tables remain shared, not refitted for that comparison.
- The **Feature heatmap** tab displays saved **scaled** biological intensities (not raw abundances or a new test). Choose a biological group field and groups, optional sample search and time/batch annotation fields, and 10–100 features ranked by variance **within the selected samples**. A maximum of 400 selected samples is enforced visibly; narrowing the selection does not recalculate saved differential tests. Euclidean/average-linkage clustering orders both axes for display. Click a feature cell or ID to inspect raw and processed intensities, download the exact plotted cells as TSV, or copy a link to these view settings; comparison views restrict the sample universe to that comparison's saved biological selection. Select **Statistics → Standard omnibus F-tests** for the saved group-wide F test and BH q-value; it is different from a named factor-adjusted model omnibus test and identifies features, not which pair differs.
- On PCA, PCoA and validated PLS-DA score plots, expand **Map metadata onto sample scores**. Add any saved sample-metadata columns as cards: categorical cards create joint legend groups; a varying numeric card can instead use a shared Viridis colour scale across groups. Only one continuous colour field is shown at a time; further numeric cards can be treated as exact-value categories. Expand **Legend groups** to move groups up or down (changing plot and legend order) or pick a colour for each discrete group; the default 12-colour palette uses saturated, contrasting colours. Repeated field names and safely distinct long values are shortened in the legend; full field names and values remain on point hover and in the group control's title. Viridis controls marker colours while a numeric field uses the continuous scale, so discrete colour pickers are unavailable in that mode. Missing numeric values stay visible in grey, and missing categories say “Not recorded” on hover. To inspect acquisition order, add `injection_order` as the Viridis card after a new run saves that column. QC diamonds and blank crosses keep their shapes. These mappings affect display only, not fitted axes, tests or recipe grouping; old sealed runs cannot acquire metadata retroactively.
- Group-colour defaults keep `QC`, `blank`, and missing-value labels such as `Not recorded`, `NA`, `ND`, and `NNA` in distinguishable grey shades instead of assigning them saturated palette colours. This applies to sample groups, categorical score mappings, and feature-point categories; biological groups retain the contrasting palette. For score plots with QC or blanks included, their roles stay grey even when a metadata category matches a biological group. Explicit colours chosen in **Display settings** or a score legend, or supplied by a plot link, take precedence.
- **Display settings** is the shared place for **Group samples by**, **Sample role**, **Groups to show**, group colours, feature-point colours, and feature-hover fields/structure source. Mapping exactly one categorical metadata column on a PCA, PCoA, or validated PLS-DA score plot also sets the shared grouping column: clicking a PCA loading then opens that feature’s intensity boxplot grouped by the same field (for example, `ATTRIBUTE_part`). Changing the grouping, sample role, or visible groups in a feature boxplot updates the shared selection and the score plots; the settings tab can make the same changes directly. These filters restrict **displayed sample points and boxplot observations only**; PCA/PCoA/PLS-DA fits, saved contrasts, volcano results, and original source tables are never recomputed. The two-group chemical-class comparison uses its own selected pair of biological groups and saved raw measurements; visiting it does not override a shared filter. Compound categorical combinations and continuous Viridis score mappings stay local because a single-column boxplot cannot faithfully represent them. Colour pickers in a score legend or Display settings update every plotted sample group with that value, including feature intensity and chemical-class plots where applicable. **Colour feature points by** and its categorical colours are shared between PCA and PLS-DA loadings and volcano points; numeric feature colours use Viridis. Saved feature-hover fields apply to all feature-point plots.
- Each interactive PCA/PCoA or PLS-DA score plot, feature-loading plot, volcano plot, PLS-DA VIP/permutation plot, Feature explorer intensity boxplot, and NPC chemical-class boxplot has **Download plotted data (TSV)**. These browser-generated files contain the plotted observations from checksum-verified saved tables, including saved coordinates/tests, sample metadata or display groups as appropriate. They follow current axes, group choices, feature/intensity stage, contrast orientation, class branch, and filters; unavailable or empty plots disable the button. Class totals are per sample and list the contributing feature IDs; volcano exports include both saved effects and display-oriented effects. The **Provenance & downloads** tab separately provides the complete original verified TSV files, including unplotted rows.
- Beside each interactive plot’s data download, choose **Copy plot link** to share that plot’s current view. The link selects the exact saved study or comparison and plot, then restores its applicable display settings: sample grouping and visible groups, colours, score axes and metadata mapping, feature ID/intensity stage/facets/significance, volcano orientation, chemical-class branch/groups/filters, and feature-hover fields. The snapshot is encoded in the URL fragment; it is not a new analysis and does not update the published run. If clipboard access is unavailable, select the URL shown below the button and copy it manually. Use the **published dashboard URL**, not a `127.0.0.1` preview, to reach collaborators. A link grants no access: recipients must already be able to open the dashboard and its saved outputs. Group names, feature IDs and display selections are recoverable from the URL, so do not share links containing sensitive labels with unauthorized people. Editing a plot after copying does not change an already copied link; copy again for a new snapshot.
- To construct a feature link without an opaque fragment, append `?run=<64-character-run-hash>&tab=features&plot=feature-intensities&feature=4782&group_by=ATTRIBUTE_part&role=sample&groups=Greenpatch&groups=Yellowpatch&stage=raw` to the published `dashboard/` URL. Repeat `groups=` for each level; without a fragment, omitting it means all groups. Optional feature parameters: `facet=<metadata-column>` and `significance=off|p|q|stars`. Set a colour with `color.Greenpatch=%2307db50` (URL-encoded `#07db50`); repeat `color.<group>=<hex>` as needed. `group_by`, `role`, `groups`, and colour overrides also apply to other relevant sample plots without changing saved analyses. Copied links retain `#view=…` for detailed metadata mappings, axes, class views, and other settings; readable query parameters override the same settings inside that fragment, so `&groups=Greenpatch&groups=Yellowpatch` can be inserted before `#view` in an existing link. With a fragment, omit `groups` to retain its selection or use `groups=*` to show all groups. Colour choices alone do **not** select groups. No short-link lookup service is shipped with this static dashboard; a content hash without a published mapping cannot resolve a view.
- In **Feature explorer → Search saved features**, use **Add feature filter** repeatedly to combine any saved candidate-record column (grouped by source), horizontal-annotation column, or MZmine input/retained feature-metadata column. For example, set **Horizontal · `sources_number_IK2D` = `3`** and **Horizontal · `isdb_score_taxo` > `5`** to keep features whose **same saved horizontal row** reports both values. Numeric columns support `>`, `≥`, `<`, `≤`, `=` and `≠`; text columns support case-insensitive `contains`, `is` and `is not`. Conditions from different sources match the same feature, but multiple conditions on one candidate source must match one candidate record (not different candidate rows). Missing values do not satisfy a filter. Free-text search also covers saved feature and annotation fields. Filters change the displayed feature list only: they do not recompute agreement, scores, analyses, or intensity plots. Sample-level metadata belongs to injections, not individual features, and is mapped in the score/feature-intensity controls instead.
- In **Feature explorer → Browse by**, switch from **Individual features** to **Reported compounds · saved 2D key** to group filtered features by the first 14 InChIKey characters reported by structural candidates or saved horizontal annotations. Click a key to list its measured features, reporting sources and source-specific candidate records; click a feature to inspect its intensities and full evidence. A feature with several reported keys appears under each one; unkeyed features remain in the individual-feature view. Filters select features before grouping, so matching a filter on one candidate does **not** validate every other reported key for that feature. A shared 2D key is not proof of identical stereochemistry or a confirmed identification. **Show structure thumbnails** adds representative saved-SMILES depictions beside feature IDs or keys for the current table page; it is off by default and sends those SMILES and your network address to the external Natural Products API when enabled.
- In a feature’s **Saved source SMILES and evidence**, an identical SMILES with the same named source and saved 2D key appears once even when both the source-specific candidate table and the horizontal summary contain it. Different candidate names and distinct saved taxonomic evidence remain listed with that structure; the untouched source-specific candidate records are available below. Unkeyed structures are not merged on SMILES alone, because identical text does not establish a shared source or identity.
- In **Chemical classes**, explicitly changing **Compare biological groups by** or **Group A/B**, or clicking a feature in the hierarchy, sets the shared grouping column, biological-only sample role, selected pair, and A/B order for its feature-intensity plot and applicable score plots. Merely visiting the two-group class comparison does not overwrite an existing shared filter. Its group colours come from **Display settings**. You can still change the feature plot's controls afterward; its intensity stage remains independent, so choose **raw** to compare per-feature intensities with class totals. Chemical-class feature filters select *features*, not sample injections, and do not recalculate intensities or tests.
- In a feature’s **Descriptive sample intensities → Display options**, select the saved intensity stage: **raw** includes measured zeros, QC and blanks; **blank_filtered** retains raw values for features surviving blank removal; **imputed**, **normalized**, **transformed**, and **scaled** contain retained biological samples only. Click the small **?** beside the stage/range to reveal what each stage means and the run’s saved methods; the guide is hidden by default. The current stage, plotted sample count and value range remain visible above the plot; two stages may genuinely have identical saved values. If a feature was excluded before a selected stage, the plot and export are cleared rather than silently showing raw values. Choose **Saved significance** to show a saved model p-value, BH-adjusted q-value, or q-value stars (`*` < 0.05, `**` < 0.01, `***` < 0.001; otherwise `ns`). This is available only when the run has a differential table and the grouping column, two biological groups, feature, and **entire plotted biological sample set** match exactly one saved contrast. Faceting or display filters that change that sample set suppress the annotation; no browser test is calculated. Even over a raw or normalized boxplot, the saved model value describes the comparison’s transformed, normalized study matrix, not a fresh test of the displayed stage. Significance is off by default.

## Paired 0.5 vs untreated example

For `mapp_project_00084/mapp_batch_00268`, make four **separate** two-group comparisons. Select `ATTRIBUTE_cell_type_treatment_concentration` as the primary group column; include only the two source levels in each row:

| Comparison | Treated source (`target: treated`) | Control source (`target: control`) |
| --- | --- | --- |
| A549 PET 0.5 | `A549_PET_0.5` | `A549_Untreated_0` |
| A549 PS 0.5 | `A549_PS_0.5` | `A549_Untreated_0` |
| MDM PET 0.5 | `MDM_PET_0.5` | `MDM_Untreated_0` |
| MDM PS 0.5 | `MDM_PS_0.5` | `MDM_Untreated_0` |

The target labels `control` and `treated` make the TUI's two-group `all` contrast `treated_vs_control`, i.e. treated minus untreated. Disable PLS-DA for the paired runs. Run two distinct recipes per row if both paired and unpaired statistics are needed. An unpaired analysis of the *same matched specimens* deliberately ignores within-unit matching; do not claim these specimens were drawn from independent donors merely to select an unpaired test.

Before making paired recipes, confirm the experimental pairing with the researcher and add a complete `ATTRIBUTE_experimental_unit` column to **curated batch metadata**. Use one ID for all five treatments within each A549 passage (three passage IDs) and one ID for all five treatments within each MDM donor/experiment (three different IDs, not just the collection date). The current MDM `ATTRIBUTE_blood_donor` is missing for one experiment, and two distinct donors share 19 June. `MDM_B_120626_PS05` carries 12 June while the source document places donor B on 19 June: verify which label/date is right; do not assume a pairing or silently correct it. Each comparison must have exactly one treated and one untreated sample per verified unit. Changes to the curated metadata change its checksum; save and run a **new study** before creating these comparisons. The old study's comparison recipes cannot reuse changed metadata.

In the comparison TUI, keep only the chosen treated and control sources, rename targets as above, choose `ATTRIBUTE_experimental_unit` under **Experimental unit / pairing block**, and type `PAIRED` after verification. For the second, unpaired recipe, use the same two groups but select the deliberate unpaired option; it leaves the block out. A manually authored paired recipe for A549 PET has the following essential fields (substitute the new study hash and one pair of sources from the table for the other three):

```yaml
kind: comparison
study_hash: "<new-full-64-character-study-hash>"
seed: 1
sample_plan:
  group_column: ATTRIBUTE_cell_type_treatment_concentration
  groups:
    - {source: "A549_PET_0.5", target: treated}
    - {source: A549_Untreated_0, target: control}
design:
  group: analysis_group
  block: ATTRIBUTE_experimental_unit
  block_verified: true
  contrasts:
    - {numerator: treated, denominator: control}
analyses:
  omnibus: {enabled: false}
  differential: {enabled: true}
  plsda: {enabled: false}
```

For its unpaired counterpart, remove both `block` and `block_verified` (keep the rest). Run the generated `validate`, `plan`, `run` commands for each recipe. When the sealed study uses `log2` transformation, the blocked two-group model tests the three within-unit differences in **log2-transformed, normalized** intensity against zero (two residual degrees of freedom); without the block it tests group differences without matching. Report the effect's direction, p-values and per-contrast BH q-values separately for each comparison.

For an explicitly selected pair, omit `name` to generate `<numerator>_vs_<denominator>` deterministically from the analysis-group targets (for example, `treated_vs_control`). Specify `name` only to override that label. The `sample_plan.groups` source-to-target mappings remain explicit: they determine which biological samples enter each group and can intentionally rename or combine source labels. With `design.contrasts: all` (or an omitted contrasts field), all distinct pairs are generated in sorted group order; use an explicit list of numerator/denominator pairs to select only the scientifically requested comparisons and their effect directions.

## What the analyses mean

Blank filtering first examines measured, un-imputed blank and biological intensities. The study saves `feature_detection.tsv` with each feature's observed-positive biological count and exclusion flags; features never observed positive in a biological sample are excluded rather than invented by half-minimum replacement. `blank_filter.tsv` also reports observed blank support. The optional QC-RSD filter uses **observed-positive pooled-QC measurements**: by default at least 80% of QC injections (and at least three measurements) must support a feature before it can pass the configured RSD limit. Imputed zeros/NA cannot make an absent feature appear artificially stable; inspect `qc_rsd.tsv` for support and exclusion reasons. For retained features, `half_minimum` replaces nonpositive/missing biological intensities with half the **feature's** positive minimum, not half the whole matrix's smallest intensity. PQN, log2 and Pareto remain configurable, not universally optimal defaults; check the prevalence, blank/QC behavior and the majority-unchanged assumption behind PQN against the experimental question ([LC–MS method evidence](LCMS_METHOD_EVIDENCE.md)).

An optional study-level `preprocessing.qc_drift` setting can fit pooled-QC-only LOESS over a validated numeric acquisition-order column; it is **disabled by default** and must not be enabled solely because QC intensity correlates with order. It needs sufficient positive QC observations and coverage, leaves missing/zero signals untouched, does not extrapolate beyond observed QC injection orders, and records per-feature fit/coverage status. Even without correction, `qc_drift.tsv` records measured positive QC support, observed-only QC RSD and order association; when enabled it also reports the before/after diagnostics. Inspect actual instrumental runs, QC trajectories, between-batch confounding and a prespecified sensitivity comparison before choosing correction. These checks do not establish a biological effect or remove confounding.

For an explicitly documented **uncorrected** study, use `preprocessing.qc_rsd_filter: {enabled: true, threshold_percent: 30, minimum_qc_fraction: 0.8}` and `preprocessing.qc_drift: {enabled: false}`. Only after validating acquisition order and QC suitability, an alternative study can set:

```yaml
preprocessing:
  qc_drift:
    enabled: true
    method: loess
    order_column: injection_order
    span: 0.75
    minimum_qc: 6
    minimum_qc_fraction: 0.8
    maximum_gap_fraction: 0.25
    maximum_fold_change: 5
```

This creates a **different** sealed study and comparisons; it must never silently overwrite the uncorrected results.

Retained **whole-study** biological intensities are transformed and scaled as configured. Shared PCA describes scaled whole-study sample variation; Bray–Curtis PCoA ordains normalized nonnegative whole-study sample dissimilarities and has no intrinsic feature loadings. Comparison omnibus tests and differential contrasts use only the selected biological sample columns from the **already transformed study matrix**, so a per-comparison normalization, filter or ordination would estimate a different quantity and is not implied. PLS-DA fits its training-fold preprocessing within each comparison: only training-observed features enter, half-minimum replacement uses the training fold's feature minima, and pooled-QC support is assessed from observed intensities. When using log2 transformation, contrast effects are log2 fold changes; Benjamini–Hochberg q-values are adjusted **within each contrast**, not across every contrast-feature combination.

PLS-DA, when enabled, reports repeated held-out predictions and label-permutation results. Completion of that validation is not proof of chemical identification, external generalization, or statistical significance. CANOPUS classes and spectral matches are candidate annotations, not confirmed identities. Review thresholds, replication, contrasts, and supervised results with the scientific owner.

### Numerical stability and reusable follow-up models

Differential contrasts and omnibus F-tests mark a feature **untestable** when its fitted standard error (or full-model residual standard deviation) is at most `1e-9` transformed-intensity units or its p-value is invalid. For such features the saved statistic, p-value and q-value are missing; Benjamini–Hochberg correction includes only testable features in each contrast or omnibus test. This prevents ratios of floating-point residual noise from being reported as evidence after constant-value imputation. Check the intensity scale before using the fixed numerical tolerance for non-log-transformed data.

Three methods formerly implemented by batch-owned scripts belong in the toolbox, not in each study:

| Reusable method | Toolbox configuration and sealed output | Choices that still belong in a batch recipe |
| --- | --- | --- |
| Near-zero-residual masking and BH correction | Standard differential/omnibus fits and saved `differential.tsv` / `omnibus.tsv` | Biological sample selection, group contrasts, interpretation |
| Factor-adjusted linear models, interactions, matched changes and nested F-tests | `analyses.linear_model` on the study's **transformed** matrix; `model_contrasts.tsv` and `model_omnibus.tsv` | Factor columns and reference levels, timepoints, unit identifiers, coefficient contrasts and named scientific questions |
| Hellinger/Euclidean PERMANOVA and centroid-spread permutation tests | `analyses.variance` on the study's **normalized nonnegative** matrix; four `variance_*.tsv` tables | Treatment/stratum columns, included groups, sensitivity scopes, seed, permutation count and interpretation |

For a comparison with two groups in multiple batches, configure a factor-adjusted contrast and an added-batch test:

```yaml
analyses:
  linear_model:
    enabled: true
    factors:
      group: {column: analysis_group, levels: [WT, mutant]}
      batch: {column: ATTRIBUTE_batch, levels: [B1, B2, B3]}
    terms: [group, batch]
    contrasts:
      - name: mutant_minus_WT
        coefficients: {groupmutant: 1}
    tests:
      - {name: batch_after_group, reduced_terms: [group], full_terms: [group, batch]}
```

Interaction fits use `terms: [group, batch, "group:batch"]`; the named model coefficient `groupmutant:batchB2` then measures how the mutant-minus-WT effect in B2 differs from B1. `coefficients` may combine multiple model terms with signed weights for a difference-in-differences. A nested test can compare `[group, batch]` against `[group, batch, "group:batch"]`. For matched trajectories, add `paired_change: {unit: ATTRIBUTE_plant_uid, time: ATTRIBUTE_timepoint, from: T0, to: T1}`; the model fits each matched unit's T1-minus-T0 transformed intensities after checking unique pairing and invariant factor values. The comparison's `sample_plan` still chooses the biological groups; it never reprocesses the parent study.

```yaml
analyses:
  variance:
    enabled: true
    group_column: analysis_group
    strata_column: ATTRIBUTE_batch
    permutations: 9999
    seed: 2803
    scopes:
      - {name: primary, exclude_groups: [reference_extra]}
      - {name: with_reference_extra}
```

Each scope reports PERMANOVA within strata, within-stratum group spread, descriptive group-centroid distances, and an **approximate** across-strata spread test that permutes stratum labels within treatment groups. Every group must have at least two replicates in each stratum. Unequal spread complicates the interpretation of PERMANOVA; neither method identifies individual metabolites or proves causality. The dashboard's **Statistical models** tab displays and filters these SHA-256-verified saved tables; selecting the tab or a feature never refits or changes the sealed tests. Link directly to a saved comparison using `dashboard/?run=<comparison-hash>&tab=statistics`.

For reproducible multi-comparison execution, run `run-recipes --dataset <batch>/recipes/dataset.yaml --recipe-dir <batch>/recipes` through `src/mapp_stats.R` in the pinned R environment. It executes each comparison YAML in filename order, reuses already completed sealed runs, and publishes the dashboard once after all comparisons succeed. Keep study-specific selections in the YAML recipes, not in batch-owned statistical or orchestration scripts.

## Results and links

Completed studies are immutable at `<batch>/results/stats/<64-character-study-hash>/`; separately sealed comparisons live at `<batch>/results/stats/comparisons/<study-hash>/<comparison-hash>/`. `run` refreshes `<batch>/results/stats/dashboard/`, its sealed-run catalogue, `biostats_params_log.tsv`, and `<batch>/results/stats/README.md`. The dashboard first selects a study, then an optional comparison: PCA/PCoA and whole-batch metadata always come from the study, while selected comparisons add inferential tables, volcano plots and comparison-specific groups without modifying the shared parent. The README computes injection and feature counts, biological groups, and enabled analyses from completed manifests; its links use `https://mapp-metabolomics-unit.github.io/<group-repo>/<mapp_project>/<mapp_batch>/results/stats/dashboard/` and `?run=<hash>`. The local `/docs/` segment is **not** part of a GitHub Pages URL.

The browser verifies published file SHA-256 checksums and does not recompute statistics. Preview locally over HTTP(S), not `file://`; for example, serve `<batch>/results/stats/` with `python3 -m http.server 8765 --bind 127.0.0.1 --directory <batch>/results/stats` and open `http://127.0.0.1:8765/dashboard/`. On a headless remote server, forward the server's loopback port to the laptop. GitHub Pages may make all published files public even if the source repository is private; check deployment access before publishing sensitive batch data.
