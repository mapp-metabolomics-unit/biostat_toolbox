# V2 environment

V2 uses pinned R 4.6.1 and its own `renv.lock`. The historical root environment still pins `MAPPstructToolbox` for legacy runs; new V2 models use released Bioconductor [`ropls`](https://bioconductor.org/packages/release/bioc/html/ropls.html) for PCA and PLS-DA and `plotly` for interactive views, without loading either the fork or Bioconductor `structToolbox`.

From `v2/`, install the pinned packages once, then use the same R version for CLI and viewer:

```bash
rig run -r 4.6.1 -f bootstrap.R
DATASET=../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/dataset.yaml
rig run -r 4.6.1 -f run.R -- validate --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/full.recipe.yaml
rig run -r 4.6.1 -f run.R -- plan --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/full.recipe.yaml
rig run -r 4.6.1 -f run.R -- run --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/full.recipe.yaml
```

The batch-owned [`dataset.yaml`](../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/dataset.yaml) contains stable input paths and optional metadata-column aliases and role labels. By default `sample_type` values `sample`, `QC` and `blank` need no role settings. Both recipes reuse this one dataset file; the CLI hashes the actual input files automatically and seals their checksums in the manifest. No SHA-256 values need to be entered manually. The owner-repository [`full.recipe.yaml`](../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/full.recipe.yaml) leaves all six original mutant groups untouched and runs PCA, PCoA, omnibus testing and 15 pairwise contrasts (the default with differential enabled), without PLS-DA. Changing a display description or an automatically added matching input-checksum guard does not create another run hash.

`run` now reports elapsed-time stage messages on stderr while checking inputs, preprocessing, running each enabled classical analysis, fitting supervised models, exporting, and sealing the result. PLS-DA shows a live 20-segment bar on an interactive terminal; redirected logs instead receive periodic completed-fit counts and percentages (at least every five percentage points or after ten seconds at the next fit). The denominator is outer held-out folds × repeats × (observed labels + label permutations), plus one full-data model fit. These are **completed model fits, not an ETA**; an individual long fit cannot report internal progress. The PLS-DA bar reaching 100% does not mean the run has been published: wait for `Completed V2 run: ...` after export and checksum sealing. `validate` and `plan` retain their machine-readable output.

PCA uses ropls on the scaled biological-sample matrix; PLS-DA uses ropls fits with a configured, rank-bounded component count in repeated stratified held-out folds. Blank/QC filtering and all intensity transformations are fitted within each supervised training fold. A label-permutation distribution tests whether held-out balanced accuracy exceeds shuffled labels; a `validated` status means the protocol completed, **not** that the result is statistically convincing. PCoA and linear-model contrasts remain separate methods, not ropls analyses.

For a validated PLS-DA run, `ropls::getLoadingMN` and `ropls::getVipVn` supply feature-aligned full-fit loadings (`tables/plsda_loadings.tsv`, LV axes) and VIP values (`tables/plsda_vip.tsv`). These descriptive fitted-model values are not held-out evidence of individual feature importance. The workflow fits PLS-DA, not OPLS-DA, so it does not produce an OPLS S-plot.

The owner's [`merged.recipe.yaml`](../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/merged.recipe.yaml) alone defines `sample_plan`: WT_N/WT_O → WT, xdhA1/xdhA2 → xdhA and xdhB1/xdhB2 → xdhB. The loader derives `analysis_group` in memory from the shared [`dataset.yaml`](../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/dataset.yaml); the recipe selects it via `design.group: analysis_group`, without copying or altering source tables. The same classical analyses and 3-fold × 5-repeat ropls PLS-DA use 99 permutations. The previous ten batch 00275 V2 runs and derived input copies were cleared at the user's request; the new full-batch and merged-group runs are sealed and published. The merged run reports held-out balanced accuracy 0.64 and a 99-permutation p-value of 0.01; review scientific limitations before interpretation.

After at least one batch recipe has completed, publish and preview the static dashboard from `v2/`:

```bash
rig run -r 4.6.1 -f ../scripts/publish_stats_dashboard.R -- --batch ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275
python3 -m http.server 8765 --bind 127.0.0.1 --directory ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/results/stats_v2
```

Open `http://127.0.0.1:8765/dashboard/` after publication. The viewer reads only checksum-verified sealed files; no Shiny process is needed. **Completed jobs** lists a stable recipe fingerprint and the specific source, scientific configuration and environment fields changed since the preceding run for that dataset. Identical parameters and inputs in the same code environment reuse a completed hash.

In **PCA / PLS-DA feature loadings** and **Volcano**, open **Display options · feature colours** to colour by saved 2D-key agreement (0–3 sources), saved ISDB taxonomic score (0–8), or numeric measured fields such as m/z. Numeric values use a continuous Viridis colourbar; **Not recorded** and conflicting **Multiple values** keep separate colours, while categorical fields retain editable per-category colours. A saved zero is distinct from **Not recorded**; agreement comes from `annotation_horizontal.tsv`, not candidate records. **Candidate record source** names candidate-table provenance (SIRIUS, CANOPUS classes or `met_annot_enhancer`), not additional agreeing structures; GNPS can contribute to agreement without a candidate record.

In **Chemical classes**, select a biological metadata field and two saved groups, then click a CANOPUS NPC pathway, superclass, class and feature to drill down. The table supports search, sort and download; paired bars show each child’s share of its parent’s mean *raw* annotated intensity, while the table includes group means and B/A. Feature selection opens its saved evidence and intensity drawer. This is exploratory composition from verified `annotation_candidates.tsv`, `matrix_raw.tsv` and `sample_metadata.tsv` for the selected sealed run—not a refit, inferred chemical identity, or differential test.
To move the foldable feature details to an external screen, open a feature from a plot and choose **Detach to window**. Selections, run changes and group colours follow the main dashboard; the detached feature picker also updates the main explorer. **Reattach here** restores the inline panel. Allow popups for the dashboard if needed; a blocked popup leaves the original panel open.
The feature-intensity **Display options** selections (stage, grouping, sample role, facet and visible groups) and menu open state persist per run across feature changes, detached windows and reloads in this browser. Returning to a visited run restores its settings; a new run starts with defaults. Clearing browser site storage resets these display-only preferences.

## Build a new recipe from the static dashboard

Open **Advanced · new analysis** in the published dashboard. Unlike the saved-result tabs, its sample metadata comes from the canonical sealed *complete* batch, not the run currently selected in the picker. Map original biological group labels to targets (the same target merges them), optionally exclude sources, and inspect the live sample-count preview. QC and blank injections remain available for preprocessing. Choose blank/QC filters, imputation, normalization, transformation, scaling, PCA, PCoA, omnibus, all-pair differential and validated PLS-DA settings. The page rejects invalid group replication, unsafe Bray–Curtis stages and insufficient PLS-DA folds before export. This is a local-plan builder, not browser-side statistics.

For batch 00275, the already prepared [`recipes/merged.recipe.yaml`](../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/merged.recipe.yaml) merges six source groups into WT, xdhA and xdhB (10 biological samples per group) while retaining seven QC and three blank injections. Both recipes use the same static dataset file; original metadata and quantification stay unchanged. To build another plan in **Advanced** after the full-batch run is complete, choose an unused slug, download its JSON and run the materializer from `v2/`; it writes only YAML to that batch's `recipes/<slug>/`, not to the toolbox or results directory:

```bash
rig run -r 4.6.1 -f ../scripts/materialize_stats_recipe.R -- --batch ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275 --plan /path/to/new-downloaded-plan.json
```

The already prepared merged recipe needs no materialization. Validate and preview it, then run only after reviewing the 99-permutation PLS-DA design:

```bash
DATASET=../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/dataset.yaml
rig run -r 4.6.1 -f run.R -- validate --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/merged.recipe.yaml
rig run -r 4.6.1 -f run.R -- plan --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/merged.recipe.yaml
rig run -r 4.6.1 -f run.R -- run --dataset "$DATASET" --recipe ../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275/recipes/merged.recipe.yaml
```

The materializer verifies a sealed canonical full-batch source and original metadata/quantification hashes, rejects changed or missing files and writes a dataset/recipe pair atomically without overwriting an existing slug. It automatically pins source checksums in the generated dataset: do not calculate or paste them yourself. For hand-authored batch recipes, omit `input_sha256`; the CLI hashes inputs automatically. The current owner full recipe uses a minimum sample/blank ratio of 2 and 50% QC-RSD threshold (717 retained features in `plan`); the merged recipe still previews 427 retained features. Earlier full-batch and merged analyses and newer full-batch runs are sealed; changing config or implementation can produce distinct immutable hashes, not overwrite them. Review scientific design before running the 99-permutation PLS-DA; enabling it alone does not establish model discrimination or feature importance. Republish after a new completed run to add its hash to the dashboard.

After completing at least one batch 00275 run, launch the separate optional Shiny viewer from `v2/` by keeping this command running and opening the **Listening on http://127.0.0.1:PORT** URL printed in its terminal:

```bash
MAPP_STATS_ROOT=../../didier-reinhardt-group/docs/mapp_project_00007/mapp_batch_00275 \
  rig run -r 4.6.1 -e 'shiny::runApp("../app", host="127.0.0.1", launch.browser=FALSE)'
```

The root must be the batch directory or an approved parent containing MAPP project/batch folders, not `results/stats_v2` or a hash. The newest completed run is selected on startup or **Refresh catalogue**; check the CLI hash against **Completed batch / run**. **All groups** is active by default; uncheck it to select visible groups, or double-click a plot legend entry to isolate its group. PCA, PCoA and validated PLS-DA scores offer independent 2D axes and 3D when three saved components exist. PCA sample scores represent samples; clicking a point in the separate PCA feature-loadings plot or in **Volcano plots** opens a collapsible right-side **Feature explorer** drawer. Feature IDs in the volcano ranked table navigate to the full Feature explorer page instead. The drawer narrows central plots while open. Source-specific saved SMILES are depicted through the public Natural Products API; structures sharing a valid saved 2D key have one representative depiction, and each original SMILES remains accessible. Met-annot-enhancer structures include reported taxa and saved Wikidata links when available. Older runs without `annotations.horizontal` cannot offer the consensus filter; candidate records with valid 2D keys can still be compared. Plotly's toolbar downloads the current interactive view; verified saved PNG/PDF buttons serve immutable original 2D PCA/PCoA/volcano plots. See the [viewer walkthrough](../docs/STATS_PIPELINE_V2.md#read-only-explorer).

The dataset/sample metadata sidebar disappears on the **Feature explorer** page; switch to another tab to adjust the saved stage, grouping or sample roles, then return to the selected feature. Changing the completed run clears the selected feature. The top Feature ID picker and annotation filters (including exact or partial-name ISDB-reported taxa) remain on the full-width page. The horizontally scrollable gallery depicts one representative structure for each known matching 2D InChIKey across GNPS, ISDB and SIRIUS; differing or unrecorded keys stay separate, and source-specific saved SMILES remain expandable. One to three named source stars show support for that key. Only the ISDB star uses the saved taxonomic score on a 0–8 pale-yellow-to-bright-green visual scale; missing scores have a neutral star, and neither color nor agreement confirms a biological or chemical identity. A default-on, optional descriptive intensity box plot sits beside the gallery; a compact table immediately below keeps **all** saved candidate records for that feature accessible independently of browse filters. Click a candidate row to focus its source record without losing the current search or filters. The separate searchable, scrollable browse table still offers selectable columns and pages through every matching record. Taxon filters use saved met-annot-enhancer records, not sample metadata, and do not filter the horizontal consensus list or the selected feature's structures and pinned records.

Every quantified feature remains available at the raw stage, even if blank or QC filtering excluded it downstream. The optional (initially shown) intensity plot and plot-driven drawer label and show saved raw peak height/area when the selected stage lacks that feature; the newest run also exports its input metadata. Batch 00275 contains peak **height** but no peak area.

Shiny chooses a free port. On a remote server, [forward its printed port over SSH](../docs/STATS_PIPELINE_V2.md#access-from-another-machine) before opening the URL on your laptop.

The extra `--` forwards options through `rig`. Install R 4.6.1 separately if it is not already available; `Rscript run.R` is an alternative when that executable selects R 4.6.1. `renv::status()` currently warns that recorded packages are unused because it scans `v2/` while the analysis source is in `../src/v2/` and the explorer in `../app/`. Bootstrap restores and checks the required packages despite this detection limit. Keep the root lockfile separate. See [the pipeline guide](../docs/STATS_PIPELINE_V2.md) for input mappings, the approved-root viewer and scientific limits.
